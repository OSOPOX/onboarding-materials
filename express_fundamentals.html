Your first server

Express is a minimal HTTP framework for Node.js. You create an app, attach routes, and call listen. That's it — everything else is layered on top of those three steps.

TS
Hello world
import express from "express";

const app = express();

app.get("/", (req, res) => {
  res.send("Hello, world!");
});

const PORT = process.env.PORT ?? 3000;
app.listen(PORT, () => {
  console.log(`Listening on http://localhost:${PORT}`);
});
TS
send vs json vs status
app.get("/text", (req, res) => res.send("plain text"));

// Sets Content-Type: application/json automatically
app.get("/json", (req, res) => res.json({ ok: true }));

// Chain status before the body
app.get("/created", (req, res) => res.status(201).json({ created: true }));

// No body, just a status
app.get("/empty", (req, res) => res.status(204).end());
i
Always call exactly one terminal method (res.send, res.json, res.end, res.redirect) per request. Calling two will throw Cannot set headers after they are sent.

Routing

A route is an HTTP method plus a path plus a handler. Express supports the standard verbs (get, post, put, patch, delete), dynamic URL segments with :param, and a parsed query string on req.query.

TS
HTTP methods
app.get("/users", (req, res) => res.json([]));
app.post("/users", (req, res) => res.status(201).json({ id: 1 }));
app.put("/users/:id", (req, res) => res.json({ id: req.params.id }));
app.patch("/users/:id", (req, res) => res.json({ id: req.params.id }));
app.delete("/users/:id", (req, res) => res.status(204).end());
TS
Route params & query strings
// URL: /users/42
app.get("/users/:id", (req, res) => {
  const id = req.params.id;       // "42" — always a string
  res.json({ id: Number(id) });
});

// URL: /search?q=express&limit=10
app.get("/search", (req, res) => {
  const q = req.query.q;          // "express"
  const limit = req.query.limit;  // "10"
  res.json({ q, limit });
});
!
Route params and query values arrive as strings (or arrays/objects for repeated query keys). If you need a number, coerce it with Number() and validate before using.

Middleware

A middleware is just a function (req, res, next) => void that runs in the order it was registered. Call next() to pass control to the next middleware, or send a response to end the chain.

TS
Custom middleware
function logger(req, res, next) {
  console.log(`${req.method} ${req.url}`);
  next();
}

app.use(logger);
TS
Built-in & path-scoped middleware
// Built-in: parses application/json into req.body
app.use(express.json());

// Path-scoped: only runs for routes starting with /admin
app.use("/admin", requireAdmin);

app.get("/admin/dashboard", (req, res) => res.json({ ok: true }));
TS
Error-handling middleware
// 4 args — that's how Express recognizes error middleware
function errorHandler(err, req, res, next) {
  console.error(err);
  res.status(err.status ?? 500).json({ error: err.message });
}

app.use(errorHandler); // register last
i
Order matters. express.json() must come before any route that reads req.body. Error handlers must come after all routes.

Request & response

req and res have lots of helpers. Mastering req.body / req.params / req.query and res.status / res.json / res.send / res.redirect / res.set covers most of what you'll write.

TS
Reading inputs from every layer
app.post("/orders/:userId", (req, res) => {
  const userId = req.params.userId; // URL segment
  const sort = req.query.sort;      // ?sort=asc
  const { item, qty } = req.body;   // JSON body (needs express.json())
  res.json({ userId, sort, item, qty });
});
TS
Status & response helpers
res.status(404).json({ error: "not found" });
res.status(204).end();              // no content
res.redirect(301, "/new-url");      // redirect
res.set("X-Trace", "abc-123");      // set a single header
res.set({ "Cache-Control": "no-store", "X-App": "onboarding" });

Body parsing & validation

To read JSON bodies you must register express.json(). Then always validate input before trusting it — the client can send anything.

TS
Enable JSON parsing
const app = express();
app.use(express.json()); // required for req.body to populate

app.post("/notes", (req, res) => {
  const { title, body } = req.body;
  res.status(201).json({ title, body });
});
TS
Manual validation
app.post("/users", (req, res) => {
  const { email, age } = req.body;

  if (typeof email !== "string" || !email.includes("@")) {
    return res.status(400).json({ error: "invalid email" });
  }
  if (typeof age !== "number" || age < 0) {
    return res.status(400).json({ error: "invalid age" });
  }

  res.status(201).json({ email, age });
});
i
In production reach for zod, joi, or class-validator. The principle is the same: reject early with a clear 400 response.

Router & modularization

Don't put every route in one file. express.Router() lets you group routes by resource and mount them under a path prefix — the same idea NestJS expresses with controllers.

TS
Build a router
// users.routes.ts
import { Router } from "express";

const router = Router();

router.get("/", (req, res) => res.json([]));
router.get("/:id", (req, res) => res.json({ id: req.params.id }));
router.post("/", (req, res) => res.status(201).json({ created: true }));

export default router;
TS
Mount the router
// app.ts
import express from "express";
import usersRouter from "./users.routes";

const app = express();
app.use(express.json());
app.use("/api/users", usersRouter);

// GET    /api/users
// GET    /api/users/:id
// POST   /api/users

Error handling

Express auto-catches synchronous errors but not async rejections (in v4). Wrap async handlers, use try / catch, and forward to a central error middleware via next(err).

TS
try / catch in an async route
app.get("/users/:id", async (req, res, next) => {
  try {
    const user = await db.findUser(req.params.id);
    if (!user) {
      throw Object.assign(new Error("not found"), { status: 404 });
    }
    res.json(user);
  } catch (err) {
    next(err); // forward to error middleware
  }
});
TS
Reusable async wrapper
// Wrap an async handler so rejections always reach next(err)
const asyncHandler = (fn) => (req, res, next) =>
  Promise.resolve(fn(req, res, next)).catch(next);

app.get("/users", asyncHandler(async (req, res) => {
  const users = await db.listUsers();
  res.json(users);
}));
!
Express 5 forwards async errors automatically. Until your project is on v5, write try / catch or use asyncHandler.

Controllers & services — NestJS preview

Once your app grows, separate route definitions (controllers) from business logic (services). This is exactly how NestJS structures everything — same idea, just without decorators.

TS
Service holds the logic
interface CreateUserDto { name: string; email: string; }
interface User extends CreateUserDto { id: number; }

class UsersService {
  private users: User[] = [];

  list(): User[] {
    return this.users;
  }

  create(dto: CreateUserDto): User {
    const user: User = { id: Date.now(), ...dto };
    this.users.push(user);
    return user;
  }
}
TS
Controller wires HTTP to the service
import { Router } from "express";

export function createUsersController(service: UsersService) {
  const router = Router();

  router.get("/", (req, res) => {
    res.json(service.list());
  });

  router.post("/", (req, res) => {
    const user = service.create(req.body);
    res.status(201).json(user);
  });

  return router;
}

// app.ts
app.use("/api/users", createUsersController(new UsersService()));
i
In NestJS the controller and service become classes annotated with @Controller and @Injectable, and the framework wires them via dependency injection. The shape is identical — thin controllers, fat services.
