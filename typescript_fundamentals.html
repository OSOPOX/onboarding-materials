Types & variables

TypeScript adds a type system on top of JavaScript. You declare what kind of value a variable holds, and the compiler catches mistakes before runtime.

TS
Basic type annotations
let name: string = "Alice";
let age: number = 25;
let isActive: boolean = true;
let scores: number[] = [90, 85, 92];

// TypeScript infers the type — annotation is optional here
let city = "Kigali"; // inferred as string
TS
Union and literal types
// Union: value can be one of several types
let id: string | number = 42;
id = "abc-123"; // also valid

// Literal type: only specific values allowed
type Direction = "north" | "south" | "east" | "west";
let dir: Direction = "north";
// dir = "up"; // Error: not assignable to type Direction
TS
any, unknown, and null handling
// any: opt out of type checking (avoid when possible)
let data: any = "hello";
data = 42; // fine, but loses type safety

// unknown: safer alternative — must check the type before use
let input: unknown = "hello";
if (typeof input === "string") {
  console.log(input.toUpperCase()); // safe now
}

// Optional values with null
let username: string | null = null;
username = "eagle";
i
Type inference means TypeScript can figure out the type from the assigned value, so you don't always need to annotate. But for function parameters and return values, always annotate explicitly.

Functions

TypeScript functions declare parameter types and return types. This makes APIs predictable: callers know exactly what to pass and what to expect back.

TS
Parameter and return types
// Always type params and return value
function add(a: number, b: number): number {
  return a + b;
}

// Optional params with ?
function greet(name: string, title?: string): string {
  return title ? `${title} ${name}` : name;
}

// Default params
function createSlug(text: string, sep: string = "-"): string {
  return text.toLowerCase().split(" ").join(sep);
}
TS
Arrow functions and void
// Arrow function syntax
const multiply = (a: number, b: number): number => a * b;

// void = returns nothing
const log = (message: string): void => {
  console.log(message);
};

// Function as a type
type Transformer = (input: string) => string;
const upper: Transformer = (s) => s.toUpperCase();

Interfaces & object types

Interfaces define the shape of objects. They're the backbone of typed APIs — every DTO, response body, and config object in NestJS is an interface or class under the hood.

TS
Defining and using interfaces
interface User {
  id: number;
  name: string;
  email: string;
  role?: string; // optional field
}

const user: User = {
  id: 1,
  name: "Alice",
  email: "alice@example.com",
};

function getUserLabel(u: User): string {
  return `${u.name} <${u.email}>`;
}
TS
Interface extension and readonly
interface BaseEntity {
  readonly id: number; // can't reassign after creation
  createdAt: Date;
}

interface Product extends BaseEntity {
  name: string;
  price: number;
  category: string;
}

// Product has: id, createdAt, name, price, category

Arrays & generics

Generics let you write reusable code that works with any type while keeping type safety. You'll see them everywhere in NestJS — services, repositories, and response wrappers all use generics.

TS
Typed arrays and array methods
const names: string[] = ["Alice", "Bob", "Carol"];
const scores: Array<number> = [88, 92, 76];

// Fully typed array operations
const upper = names.map((n: string): string => n.toUpperCase());
const high = scores.filter((s): boolean => s >= 90);
TS
Generic functions
// T is a type parameter — replaced at call time
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}
first([1, 2, 3]);     // returns number | undefined
first(["a", "b"]);  // returns string | undefined

// Generic response wrapper — common in NestJS APIs
interface ApiResponse<T> {
  data: T;
  success: boolean;
  message: string;
}

const res: ApiResponse<User> = {
  data: { id: 1, name: "Alice", email: "a@b.com" },
  success: true,
  message: "OK",
};

Classes

TypeScript classes combine interface-style typing with object-oriented structure. NestJS services, controllers, and guards are all classes — understanding access modifiers and constructors is essential.

TS
Class with typed properties
class UserService {
  private users: User[] = [];
  readonly maxUsers: number = 100;

  // Shorthand: public serviceName: string is set by constructor
  constructor(public serviceName: string) {}

  addUser(user: User): void {
    if (this.users.length < this.maxUsers) {
      this.users.push(user);
    }
  }

  findById(id: number): User | undefined {
    return this.users.find((u) => u.id === id);
  }
}
!
Access modifiers: public (default, accessible anywhere), private (only inside the class), protected (class + subclasses). NestJS services use private readonly for injected dependencies.

Async / Promises

Almost every NestJS service method that touches a database or external API is async. TypeScript types Promises and async functions — Promise<T> is the return type of any async function.

TS
Typed async functions
// Return type is Promise<T>
async function fetchUser(id: number): Promise<User> {
  const res = await fetch(`/api/users/${id}`);
  const data: User = await res.json();
  return data;
}

// Promise<void> for no return
async function sendEmail(to: string): Promise<void> {
  await emailService.send(to);
}

// Error handling
async function safeLoad(id: number): Promise<User | null> {
  try {
    return await fetchUser(id);
  } catch {
    return null;
  }
}

Decorators — NestJS preview

Decorators are a TypeScript feature that NestJS uses extensively. They're functions prefixed with @ that annotate and modify classes, methods, and parameters. You don't need to write decorators today — just recognize and read them.

TS
What decorators look like in NestJS
import { Controller, Get, Post, Body, Param } from "@nestjs/common";

@Controller("policies")          // maps to /policies
export class PoliciesController {

  @Get()                         // GET /policies
  findAll(): string {
    return "returns all policies";
  }

  @Get(":id")                    // GET /policies/:id
  findOne(@Param("id") id: string): string {
    return `policy #${id}`;
  }

  @Post()                        // POST /policies
  create(@Body() dto: CreatePolicyDto): string {
    return "creates a policy";
  }
}
i
The TypeScript fundamentals you learned today — interfaces, classes, generics, async — are exactly what powers this controller. CreatePolicyDto is a class. The service methods are async. The class structure is what you built in lesson 4.
